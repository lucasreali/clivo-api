`TenantRepository` was the only Spring Data repository in the project living in a module's public root package. `core/access/AccessService` was the single consumer outside `common.tenant`, and it used exactly one operation: resolve the `Tenant` bound to the current request.

The repository now lives in `common/tenant/internal`, and `common/tenant/TenantDirectory` (a `@Service`, `@Transactional(readOnly = true)`) exposes the one thing the outside needed: `Optional<Tenant> current()`, which reads the id from `TenantContext` and loads the row. `AccessService` injects `TenantDirectory` instead of the repository; its private `currentClinic()` is now a single delegation.

`TenantContext` was deliberately left alone rather than given the repository: it is a `ThreadLocal` holder bound by `TenantResolutionFilter` and read by `RequestTenantIdentifierResolver` on every Hibernate call, so giving it a data-access dependency would put a query behind what callers read as a field. `TenantDirectory` composes the two instead.

`findByCode` on the repository is currently unused; it was carried over untouched with the move.

This keeps the rule the rest of the codebase already follows: inside a module only the root package is public API, repositories live in `internal`.
