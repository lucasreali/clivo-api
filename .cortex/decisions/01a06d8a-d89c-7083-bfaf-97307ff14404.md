`@RequiresModule`, `ModuleActivationState`, `RequiresModuleInterceptor` and `ModuleGuardConfiguration` all sit in `common/extension`, not in `configuration`. The core and the feature modules must be able to annotate a controller without importing `configuration`, and `common` is the only OPEN Modulith module, so the port and the machinery that reads it belong together there. `configuration/modules/internal/StoredModuleActivationState` is the only implementation.

The interceptor throws `ResourceNotFoundException("resource", request.getRequestURI())`, producing a 404 whose message names only the path. A 403 would confirm that the feature exists and is merely switched off, which is exactly the trace the "a disabled module leaves no trace" rule forbids. The same rule drives the capabilities resource: `CapabilityService` omits inactive modules entirely and hides every parameter whose `module_code` points at an inactive module, so a client never sees `"inventory": false`.

An endpoint without the annotation is never hidden, and the guard reads the annotation from the handler method first, then from its declaring class.
