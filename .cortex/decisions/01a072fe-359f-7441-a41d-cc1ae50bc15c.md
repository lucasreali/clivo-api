`ArchitectureTest` (src/test/java/com/example/clivoapi/ArchitectureTest.java) states the boundaries ArchUnit checks: the core does not know the modules, the core reaches configuration and patterns only through `common/extension`, and `common` depends on nobody.

The rules name packages as `com.example.clivoapi.core..`, not `..core..`. A bare `..core..` also matches `org.springframework.security.core`, and `..configuration..` matches `org.springframework.security.config.annotation.web.configuration` — both fired false violations on `AuthenticatedAuditor` and `SecurityConfiguration` before the patterns were anchored to the project root.

`ModularityTest` keeps enforcing the Spring Modulith boundaries and the encapsulation of the `internal` sub-packages, so ArchitectureTest deliberately does not repeat those; it states the architectural rules of the assignment in a form that reads as prose.
