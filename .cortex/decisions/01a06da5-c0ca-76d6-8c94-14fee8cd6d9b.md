`core/catalog` holds an entity called `Service` (table `service`) and a Spring bean called `CatalogService` — named that way so it does not become `ServiceService`. Both live in the same package, so the simple name `Service` inside that package resolves to the entity.

`CatalogService` therefore writes `@org.springframework.stereotype.Service` in full rather than importing it. Importing `org.springframework.stereotype.Service` would shadow the entity for the whole file and force the *entity* to be fully qualified instead — the worse trade, since the file is about the entity. Any future class in `core/catalog` faces the same choice.

`Money` lives in `common/money` as an `@Embeddable` record over a single `BigDecimal`, normalised to scale 2 with `HALF_UP` so equality is by value and not by scale, and refusing a negative amount with `BusinessException` (422). Its column is named `amount`, so each use site renames it: `Service.price` carries `@AttributeOverride(name = "amount", column = @Column(name = "price", ...))`. `common` is an OPEN module, so `core`, `patterns` and `modules` can all reach it — which is why `Money` is not in `core`, where billing (5.1), insurance (6.7) and commission (6.9) would each have to import another module's package.

`ServiceDuration` is an `@Embeddable` record over `duration_min` enforcing the table's `CHECK (duration_min BETWEEN 5 AND 480)` in code as well, and owning `endFrom(LocalDateTime)` — the calculation phase 3.2 uses to derive an appointment's `ends_at` from its start.
