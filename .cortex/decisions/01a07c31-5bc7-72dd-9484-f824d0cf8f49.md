Tenant isolation may not depend on a request field. Sign-in used to take a clinic code alongside the credentials, and SessionController copied the resolved clinic into an HTTP session attribute that TenantResolutionFilter read back on every later request. A caller could therefore name a clinic in the sign-in body.

Now: SignInRequest and SignInAttempt carry email and password only. AccessService.signIn finds the user by email alone and reads the clinic from the persisted AppUser row. TenantResolutionFilter reads SecurityContextHolder, casts the principal to the new common/tenant/TenantBoundPrincipal port (implemented by AuthenticatedUser, alongside AuditorIdentity) and binds that tenant. No header, parameter, body field or session attribute path is left; TENANT_SESSION_ATTRIBUTE was deleted rather than kept as a fallback.

This required email to be unique across the platform: migration V11__global_user_email.sql replaces the per-tenant index ux_app_user_email on (COALESCE(tenant_id, zero-uuid), lower(email)) with a global one on (lower(email)). AppUserRepository lost findByClinicCodeAndEmail, findByClinicIsNullAndEmail and existsByClinicIdAndEmail in favour of findByEmail and existsByEmail. Accepted trade-off: a person working at two clinics needs two accounts with two different email addresses.

AccessService.signIn now returns SignedInSession(AuthenticatedUser, TenantIdentity) so SessionView can show the client the clinic it resolved (id, code, name). The client receives the clinic; it never sends it. AuthenticatedUser's own record shape was left untouched on purpose so the security principal and every existing caller keep compiling.

Because the filter now depends on the security context rather than the servlet session, it must run inside the Spring Security filter chain. It does: the chain is registered at order -100 and a plain @Component OncePerRequestFilter defaults to LOWEST_PRECEDENCE, so it is nested within it.

Rejected: keeping the clinic code as an optional disambiguator. Any request-supplied tenant hint reopens the hole, and a fallback path is the hole.
