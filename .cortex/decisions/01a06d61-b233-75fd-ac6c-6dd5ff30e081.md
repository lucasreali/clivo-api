Spring Data JPA auditing fills `created_at`, `created_by`, `updated_at` and `updated_by` through `AuditableEntity`, a `@MappedSuperclass` annotated `@EntityListeners(AuditingEntityListener.class)`, enabled by `@EnableJpaAuditing` in `AuditingConfiguration`.

`AuditableEntity` extends `TenantScopedEntity` rather than standing beside it. Java allows a single superclass, and an entity that is both tenant-scoped and audited would otherwise have to pick one of the two. Chaining them is safe here because the physical schema has no audited table without a `tenant_id`. Entities that only need tenant scoping extend `TenantScopedEntity` directly; the audit level is opt-in on top.

The auditor is resolved by `AuthenticatedAuditor`, which reads the Spring Security principal and only yields an id when the principal implements the `AuditorIdentity` port declared in `common/audit`. This keeps `common` free of any dependency on `core/access`: `AppUser` implements the port when it lands in task 2.1, and until then the auditor simply resolves to empty.

Note that the columns are unevenly present across the physical schema (for instance `customer` has `updated_by` but no `created_by`), so most entities will not extend `AuditableEntity` — it is for the tables that carry the full four-column trail.
