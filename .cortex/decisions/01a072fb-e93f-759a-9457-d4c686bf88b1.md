`ReuseTest` (src/test/java/com/example/clivoapi/patterns/ReuseTest.java) is the file that demonstrates the reuse criterion of phase 7.1: one method per pattern, each adding a new participant declared inside the test itself.

Chain and Abstract Factory need nothing but a `@TestConfiguration` bean: the appointment chain is `List<AppointmentValidator>` ordered by `@Order`, and the field catalogue is `Map<String, FieldFactory>` keyed by bean name, so a new validator or a new field type joins by existing.

The Strategy needed one extra step. `BatchService.currentPolicy()` resolves `Map<String, ExpiredBatchPolicy>` by the *value* of the `block_expired_batch` parameter, and that parameter is declared `BOOLEAN` in the `parameter` catalogue, so `ClinicParameterService.change` only accepts `true` or `false`. The test therefore registers a third policy bean named `quarantine` and widens the catalogue row to `ENUM` with options `["true","false","quarantine"]` through `jdbcTemplate`, restoring it in `@AfterEach`.

That is deliberate, not a workaround: mechanism C keeps the accepted values in data, so a third policy costs one new class plus one catalogue row and no production class is edited — which is exactly the claim the test has to make. Rejected alternatives: inserting the `tenant_parameter` row by raw SQL (bypasses the service and proves less) and overriding the bean named `true` (a replacement, not an addition).

Test fixtures for phase 7 live in `com.example.clivoapi.support` (`ClinicFixture`, `Clinic`), public so both `patterns` and `scenarios` can extend them; the phase 0-6 fixtures were left untouched.
