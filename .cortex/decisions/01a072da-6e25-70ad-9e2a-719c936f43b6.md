The Strategy classes for 6.5 already existed from 4.4 (`RoleAccessPolicy` in `common/extension`, `SegregatedRoleAccessPolicy`/`SingleRoleAccessPolicy` in `patterns/strategy`, resolved by `RoleAccess` from the `role_model` parameter). What was missing was the acceptance criterion: reception gets 403 on the financial report under SEGREGATED and 200 under SINGLE, with no user role changed.

Added: `allowsFinancialReport(ViewerRole)` on the port (segregated → MANAGER only, single → everyone); `RoleAccess.requireFinancialReport(role)` which throws the new `common/exception/ForbiddenOperationException`, mapped to 403 by `ApiExceptionHandler`; and the report itself — `ReportPeriod`, `BillingReport`, `BillingTotals`, `BillingService.reportOf(period, viewer)` over `invoice.due_date`, exposed as `GET /api/invoices/report`.

403 here, not 404: this is a permission inside a feature the clinic has, not a module it never contracted. The 404-no-trace rule belongs to `@RequiresModule` and stays there.
