6.6 wires `PackageSessionConsumer` (an `EncounterCompletionListener` in `modules/sessionpackage/internal`) to deduct one session when an encounter completes. Two things it needs that were not obvious:

Ordering. Two listeners now react to the same event and one depends on the other's output: the package can only zero an invoice that already exists. `InvoiceIssuer` carries `@Order(InvoiceIssuer.FIRST)` (0) and `PackageSessionConsumer` `@Order(AFTER_INVOICING)` (100). Relying on the container's bean order would have been a coin flip.

No new port. `InvoiceCoverage.SESSION_PACKAGE` was already core vocabulary from 5.1, so the module calls `BillingService.coverByPackage(encounterId)` directly rather than introducing an adjustment extension point — core still names no module. The percentage-based adjustment port belongs to 6.7 (insurance), where the value, not just the coverage flag, has to come from outside.

`Invoice.coverBy` also fills `discountReason` ("fully covered by SESSION_PACKAGE"): V6's `invoice_discount_reason_required` check refuses a non-zero discount with no reason, and 5.1 wanted the origin declared anyway.

"An encounter consumes at most one session" is enforced twice: `SessionPackage.requireUnused(encounterId)` gives the readable refusal, `package_usage`'s `UNIQUE (encounter_id)` is the backstop.
