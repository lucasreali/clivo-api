The frontend generates its typed client from the API contract with Kubb, so the OpenAPI document is a build artefact of this repository rather than something the frontend reverse-engineers.

springdoc already produced a usable document from the Spring annotations alone, but its `operationId` defaults to the Java method name, and the handler names collide badly across controllers: `findOne` appears 11 times, `register` 7, `describe` and `deactivate` 6 each. springdoc breaks ties with numeric suffixes, so a generator emits `findOne`, `findOne_1` ... `findOne_10` as function names. Every endpoint therefore carries `@Operation(operationId, summary)` naming the operation in domain terms (`getCustomer`, `settleInvoice`, `closeCommissionPeriod`), and every controller carries a `@Tag` so the generator groups files by subject.

`OpenApiSpecificationTest` writes `openapi.json` at the repository root during `./gradlew test`, so the committed document cannot drift from the code and a contract change appears in the diff of the commit that caused it. `springdoc.writer-with-order-by-keys` keeps that output stable between builds. The same test guards the rule: it fails when an endpoint declares no `operationId` or when two share one, which is what stops the collision problem from coming back with the next endpoint.

Error responses were left to springdoc, which propagates the two `@RestControllerAdvice` classes onto every operation: 401 from `AccessExceptionHandler`, and 403/404/422 from `ApiExceptionHandler`. springdoc ignores the `MethodArgumentNotValidException` handler, so the 400 is declared by `RejectedPayloadResponse`, an `OperationCustomizer` that adds it only to operations that carry a request body — the only ones that can answer it.

Authentication is described as an APIKEY-in-cookie scheme over `JSESSIONID`, required globally, with `POST /api/session` exempted through `@SecurityRequirements`.

Rejected: serving the document only from `/v3/api-docs` at runtime, which would force the frontend to run the API and a database before generating; and a Gradle task writing to `build/`, which leaves nothing reviewable in a pull request.
