Every activation and deactivation of a module is now recorded in a dedicated entity, ModuleActivationChange (table tenant_module_history, migration V13), instead of being written into the shared audit trail (AuditEntry / audit_log).

Reason for rejecting common/audit: AuditedRecord identifies the audited record by a UUID (audit_log.record_id UUID NOT NULL), and a module activation has no UUID identity - it is keyed by (tenant_id, module_code). Reusing AuditEntry would have meant fabricating a record identifier or hiding the module code inside the old_value/new_value JSON. audit_log.user_id is also NOT NULL REFERENCES app_user(id), while the author of an activation is optional, exactly as the existing tenant_module.enabled_by column already models it.

ModuleActivation.enable(author) and disable(author) now return the ModuleActivationChange they produce, so the history is a by-product of the state change on the entity rather than separate bookkeeping. ModuleActivationService writes it through ModuleActivationTrail, which also owns the AuditorAware lookup, keeping the service at four collaborators.

The history is read through the platform module, scoped to the clinic in the path: GET /api/platform/tenants/{tenantId}/modules/history (operationId listClinicModuleHistory).
